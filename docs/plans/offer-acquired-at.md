# Use `acquired_at` throughout the offer pipeline

`acquired_at` is the UTC instant when sourcing finishes successfully fetching an offer from the retailer. Capture it once per successful fetch at microsecond precision. Use `acquired_at` in Rust, JSON, REST, and SQL, and `acquiredAt` in GraphQL.

## Capture and storage

- **HTML offers.** Rename `offer_details_raw.fetched_at` to `acquired_at` and remove the column’s `DEFAULT now()`. Make the download handler’s timestamp a required value on a newly fetched raw offer. Pass it explicitly to the Diesel insert record and use the incoming record’s value on conflict. A repeat download must update the object reference and acquisition time together. The raw row, storage metadata, and download event must all carry the same instant.
- **GraphQL offers.** At the capture in `steps/graphql/offer_details/mod.rs`, truncate the clock immediately after the complete fetch succeeds. Define one helper in `services/retailer_sourcing/src/steps/mod.rs` for both fetch handlers, taking a UTC instant and returning `instant.trunc_subsecs(6)`. Move the splice from `apps/development/src/offer_details_dump.rs` (`source_payload`) to capture. It already parses the complete JSON, requires an object, and rejects an existing root key. Preserve leading JSON whitespace (space, tab, CR, LF) and reject a UTF-8 BOM. Immediately after the root opening brace insert `"acquired_at":"<value>",` for a nonempty object and omit the comma for an empty object, including `{ }`. Splice into the original text so all other bytes survive. Use that same value in storage metadata and `OfferDetailsFetched`. Reject a malformed root or an existing `acquired_at` before writing.
- **Extraction and dumps.** Remove the `or_insert` injection in `steps/graphql/extract_offer_details/mod.rs`. Validate that the root `acquired_at` is present, parses as a timestamp, and equals the command’s instant. On success pass the original raw body directly to `extract_v2_for` and remove timestamp injection from the dump tool. Update the development listing queries to order HTML rows by `acquired_at` and read `acquired_at` from GraphQL event payloads. Rename the GraphQL development v2 REST response field and the dump client’s corresponding field to `acquired_at`. Preserve existing tie-breakers.

## Downstream contracts

- Rename the offer timestamp in sourcing commands, events, saga builders, derived storage metadata, exports, import payloads, Offers aggregate state, and both read projections. Rename `OfferScrapedAtUpdated` to `OfferAcquiredAtUpdated`, including its persisted tag, routing, and subscribers.
- Add reversible migrations in all three services. Retailer Sourcing gets the HTML column and default changes above. The old URL/time index was already dropped. On the empty `offer_export` table drop the three-column unique constraint and `schema_version` column with its check, then add `UNIQUE (offer_id, source_object_id)`. Change snapshot lookup and the insert’s `ON CONFLICT` target to that pair. The down migration restores the positive, non-null version column (use 1 solely to satisfy the constraint if rollback encounters rows) and the original triple key. Offers renames `read_offers.scraped_at`, and Customer Facing renames `offers.scraped_at`. These last two migrations are schema-only column renames on empty projections. Keep the runtime ordering rule that an older import cannot move the projected acquisition time backward.
- Enforce a required timestamp in Retailer Sourcing’s offer types through its outgoing import payload. Offers applies the same optional-input rule regardless of inbox source. The manual REST import currently permits omission and feeds the shared Offers inbox. Retain optionality on that request and the shared Offers command, creation event, state, and read models that must represent a manually created offer. A sourced writer must always supply a time. Never synthesize a time for a manual request.
- For GraphQL imports use storage metadata as the authoritative acquisition instant. Compare every structured variant’s `acquired_at` with it before emitting imports. Fail the whole batch on a mismatch, including for a variant that would otherwise be skipped. Test a mismatched variant and verify no outbox messages are recorded.
- Update REST/OpenAPI, GraphQL, Bruno requests, fixtures, service documentation, and the offer walkthrough. Add and index an ADR superseding ADR 26 and identifying the specific export and creation-event version clauses it replaces in ADRs 19, 24, 25, 28, 29, 34, 35, 36, 37, 38, and 40. A search of the ADR text through both 0090 records for creation tags, export versions and schema versions found no additional retention rule after 40. The schema versions in ADRs 51, 57, 59 and 81 belong to raw artifacts. Use the next unused ADR number (currently 0091). Verify the sibling Shopify artifact and retailer crates against the stamped raw body. Their models already use `acquired_at`. Sitemap fetch time and token acquisition time remain independent lifecycle fields.

## Version contracts

Retire versioning only for the three timestamp-bearing contracts below.

- Collapse `OfferCreated.v1` through `.v10` to the literal persisted event type tag `OfferCreated`. Remove the persisted aliases, version-specific creation records, `LegacyOfferCreatedEvent`, and the untagged `OfferCreatedWire` fallback. Keep the current creation fields.
- Replace `OfferScrapedAtUpdated.v1` with the single unversioned `OfferAcquiredAtUpdated` tag. Use the same names in storage, publication, and consumption.
- Collapse offer export/import to the current payload shape with `acquired_at`. Remove export/import `schema_version` fields, defaults, branch selection, and version-based snapshot lookup or uniqueness. Delete `import_payload_v2.json` through `import_payload_v8.json` and replace the contents of `import_payload.json` with the single current fixture shared by Retailer Sourcing, Offers, and Customer Facing. Rewrite Customer Facing’s version-loop projection test to read that fixture once and assert its current pricing, availability, condition, content, and timestamp directly. Keep the retailer source examples.
- Under this scope, other event tags and Shopify raw artifact schema versions keep their own contracts. Record every superseded version-retention rule in the new ADR while retaining the corresponding pricing, content, localization and identifier semantics.

## Reset and verification

- The operator performs the reset manually using the service databases during cutover. Document these runbook steps. Stop all workers and outbox delivery and suspend incoming writes. Wipe all Retailer Sourcing raw and derived rows, queues, event streams and exports, the Offers event store and `read_offers`, and Customer Facing `offers`. Clear associated pending delivery, queue and replay state so old messages cannot repopulate the empty projections. This reset deliberately discards manually imported REST offers as well. Leave old object-storage contents in place as unreferenced objects. After the wipe, migrate the empty databases, deploy all three services, then resume processing and writes together.
- **HTML regression test.** Store an offer with a known acquisition time well before database `now()`, then download the same offer again with a second known time. After each write, assert that the row, object metadata, and event agree exactly. Verify that the development listing orders by acquisition time.
- **GraphQL and downstream tests.** Trace a known timestamp through stored raw JSON, extraction, structuralization, dump, import, and public reads. Use a deterministic clock with nonzero sub-microsecond digits and assert exact equality of the truncated instant in raw JSON, metadata, the event, and the persisted database value. For capture, assert exact raw bytes using a long numeric literal, nonalphabetic key order and an escaped string. Include leading whitespace, empty and nonempty objects, BOM rejection, a non-object root and an existing key. The byte-preservation assertion ends at raw storage. Extraction and structuralization use their existing typed numeric and money contracts; run their existing conversion tests. Test missing and mismatched root timestamps as separate extraction failures. Cover manual REST omission, required timestamps on sourced inputs, out-of-order imports, and the renamed event and API fields.
- Exercise each migration up and down. Exercise duplicate export preparation for the same offer/source pair and verify one snapshot. Skip the uncompiled duplicate under `services/retailer_sourcing/src/offer_discovery/`. Review remaining uses of `fetched_at`, `scraped_at`, and their case variants against their meaning. Run `make fmt`, `make ci`, affected PostgreSQL and smoke tests, and live health or page checks for each changed service and app.
